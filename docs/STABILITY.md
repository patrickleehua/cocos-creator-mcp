# 稳定性、验收范围与发布条件

本文说明 0.1.0 的证据边界。工具存在、原生请求返回、读回成功、浏览器实际运行和长期稳定是不同层次，不能互相替代。

当前定位为**实验性公开测试版**。维护目标是先保证工程身份、修改结果和失败恢复，再扩展专用功能。一次回归通过不能作为“零风险”或生产稳定承诺。

## 当前实现的稳定性约束

- MCP 与编辑器运行时隔离，扩展使用 Node 14 兼容的 CommonJS 和内置模块。
- 原生消息 manifest 缺失、损坏或没有有效 methods 时关闭对应能力；不将“清单不可读”解释为支持全部命令。
- RPC 串行化，有限缓存去重；客户端断连不提前释放仍在执行的原生操作。
- 写操作不自动重试。`outcome:unknown` 后先查询现场，避免把不确定结果重放为第二次修改。
- 修改使用原生消息并进行相应读回；保存、未保存保护和部分完成的语义见[操作说明](OPERATIONS.md)。
- 扩展的加载、卸载、启动、停止串行执行；停止结束前不启动第二个 bridge，清理失败后仍释放适配器引用。
- 构建启动前检查原生队列，存在活动任务则拒绝。构建 Promise 结束前保持 busy；取消只作用于能确认归属的任务。
- 多个场景窗口、未就绪场景和未保存修改会阻止相关预览、构建或场景写入。

这些约束不提供跨多个 MCP 客户端的业务事务，也不能对编辑器 UI 的人为并发操作加锁。自动化执行期间避免同时手动编辑或构建。复杂操作发生部分失败时需要恢复现场。

## 安装与更新

安装器只接受具有有效名称、工程 UUID、`creator.version: 3.7.x` 和 assets 目录的工程。源目录、工程和目标扩展路径中的符号链接 / junction 会被拒绝；使用真实目录路径。

更新需显式 `--update`，并核对已有目录确实具有本扩展的入口、消息和场景脚本结构。同名的无关目录不会被覆盖。当前版本管理的文件会被替换，额外文件保留；文件与目录冲突则报错。

流程为：获取工程内安装锁 → 复制到临时目录 → 校验文件内容与工程身份 → 将旧扩展移至备份 → 替换为完整新目录。正常复制或替换失败会保留旧版或执行回滚；回滚失败时保留备份，并在错误中报告恢复路径。

这不是文件系统断电事务。强制结束进程、系统断电、磁盘损坏或恢复阶段失败，仍可能留下 `extensions/.cocos-creator-mcp-install-*` 和安装锁。遇到 `INSTALL_BUSY` / `INSTALL_ROLLBACK_FAILED`：

1. 关闭目标 Creator，确认没有安装进程或构建继续运行。
2. 保存错误信息，检查目标、临时目录和其中的 `previous` 备份，先复制备份到安全位置。
3. 核对备份确为该工程的完整扩展，再恢复；不要用泛化清理命令删除整个 extensions。
4. 确认恢复完成且没有其他安装进程后，移除对应遗留锁，再重新安装。

### 标记为稳定版之前

除上述条件外，还需通过长期运行、故障恢复、重连和真实社区工程回归；对承诺的版本 / 系统 / 构建目标逐项提供证据。新增工具不能跳过同样的失败路径、读回和持久化验证。

目前缺少这些证据，故不建议标成 production-ready 或承诺“非常稳定”。这是发布门槛，不能通过修改 README 措辞代替实际执行。
